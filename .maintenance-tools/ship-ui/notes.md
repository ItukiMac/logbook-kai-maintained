# 艦娘一覧の配布用status JARへの分離 — 2026-10-28

基点: PR63統合 `30d9c17e25adb9bdcffdf41c6ac71841a6f240ed`。
この文書は実装範囲と検証項目を示す。最終headのCI・統合結果はPRの実結果で確認する。

## 実装

ShipController、ShipTablePaneとすべての内部セル・出力ヘルパー、ship.fxml/ship_table.fxmlを
本体からstatus機能JARへ分離する。既にcharts側にある統計タブと同じ艦娘ウィンドウで共存する。
本体＋3機能JAR、7つの登録機能ID、同一本体ハッシュ条件と旧公開型・設定キーを維持する。
新しい第4の機能JARは追加せず、艦娘一覧の更新単位はstatusである。

`ShipTableUiV1.Pane` がenable/disable/updateの公開ライフサイクルを提供する。
共有の非公開パラメータフィルターは本体の `ShipUiBridgeV1` が生成し、公開アダプター越しに接続する。
表の列設定・選択・保存、確認ダイアログ、画像ズーム、FXMLのロードは公開GUI窓口を使う。
子テーブルFXMLの所有者をShipTablePane.classに固定し、サブクラスや本体の代替リソースへ戻らない。
Window所有者の保存・ダイアログAPIを追加し、既存のStage所有者シグネチャは残す。

## 配布検査

新プロファイル `ship_ui_profile: ship-ui-in-status-v1` と本体の `ShipTableUiV1.class` を対応させる。
新本体のプロファイル欠落、旧本体への偽の宣言、未知プロファイル、本体残留、別JARへの誤配置、
必須クラス/FXML欠落を起動前に拒否する。従来のv2配布は従来どおり読める。
パッケージ生成先は新規の別ディレクトリのみ。元JARを編集・削除しない。

## 試験項目

- Javaの公開型互換、内部クラスを含む非公開GUI依存検査、既存コンストラクタ/出力メソッド維持。
- Python合成アーカイブの旧形式/正常分割、プロファイル欠落/偽装、誤配置/欠品拒否。
- 実配布のstatus JARから艦娘ウィンドウと子テーブルを開く。本体側に対象クラス/FXMLがないことを検査。
- 全員/全艦隊/各艦隊/ラベル別タブ、並び順、テキスト/数値/ラベルフィルター、選択コピー。
- 既存の制空権シミュレータJSON・艦隊晒し文字列・デッキビルダー形式を合成艦で確認。
- 旧設定キーへの保存/再読込、ウィンドウを閉じた後の更新タイマー停止、元履歴と入力JARのバイト保持。
- 前PRの実ラベルダイアログ（キャンセル/確定/競合拒否）と統計5グラフも新しい配布で再実行。

合成データ・隔離runnerのみ。本人の艦娘/設定/履歴・Mintは試験に用いない。

## 完了と取り違えない範囲

これはGUIの実配布単位の分離であり、艦娘全ドメインの不可変化ではない。
旧ShipItem、Ship/SlotItem、ShipFilter、DeckBuilder、共有画像/補完、画面設定型は本体に残る互換契約。
一覧の行は依然として旧可変型を持つ。全writerの同期・読取トランザクション・任意本体間のABI互換は未完成。
製品クラスローダーは共有のまま。第三者隔離やホットリロードは追加しない。

任務・基地・残る補助処理、全148定義の意味認証、未知データ形式変換、Mint実機/IME/実Chrome/ゲーム通信、
