# Issue移管用の残件 — 2026-10-27

## 登録状態

ユーザーの指示: 「限定的なバグはissueに残して全体の更新作業を完了」。
実際にGitHub Issue作成APIを実行したが、HTTP410 `Issues has been disabled in this repository.` で拒否された。
**この一覧はGitで保持する移管原稿であり、実Issueを登録済みとはしない。番号を捏造しない。**
Issuesを有効にできた後、各見出しを個別Issueへ移管し、その番号とURLをここに追記する。
既存の受入条件・未完了タスクは消さず、限定的な既知制限で通常の互換更新を無期限に止めない。

## 限定的な問題・未確定条件（通常の互換更新の非ブロッカー）

### LIMIT-01: 出撃中の再起動後、連続性が不明な到達を加算できない

- 対象: `PortArrivalRuntime`、PR #52/#55。
- 再現条件: START保存後の停止中に母港→同じ編成で別出撃→同じセルへ戻ったケースは、時刻/艦隊/前セルだけでは区別不能。
- 現状: #55で誤加算は修正済み。`RESTART_CONTINUITY_UNPROVEN`で不加算とし、新しい母港/startの観測から再開。journal/到達/pendingを保持。
- 影響: ゲーム側進捗は変更しないが、アプリ表示が過少になる。連続観測・重複拒否・確定退避は検証済み。
- 完了条件: 捕捉元の永続識別子または欠落のない再生による連続性証明。停止中別出撃、再送、受諾期間、時計逆行、旧形式の回帰試験。不明時の不加算を弱めない。

### LIMIT-02: 現行季節版の内部ID・有効期間・実観測が不足する任務は未確定

- 対象: 840/841/843/906/954を含む季節版カタログ、PR #53/#55。
- 現状: 根拠のある2021/2025歴史版と選択機構を実装済み。年度や同名だけで現行IDを推定せず、期間外・観測不一致を未確定にする。
- 影響: 根拠不足の現行版を自動判定できない。旧成功表示を現在版へ流用しない。
- 完了条件: 公式告知と指定Wiki/ぜかましの版・期間、内部IDと実questlist観測を対応付け、ハッシュ/期間/受諾の境界試験を追加。2026版を確認済みと捏造しない。
- 証拠: `seasonal-source-checks-20261027.json`、`seasonal-rules-20261027.md`。
