# R4：分割版の通常起動・一式切替/復元と任務条件の照合

基点は `238001262600d2813c6af19216a99df0f28eb733`。対象は依頼1・2。Mint本番、auto.sh、既存JAR、設定、履歴、既存プラグイン、バックアップを変更しない。公開・改名・旧環境の削除も行わない。

## 1. 分割版の通常起動と版管理

`scripts/feature_bundle_manager.py` はPOSIX専用の明示実行ツール。既存環境を取り込まず、**新規に初期化した管理領域だけ**を受け付ける。R3の分割ビルダー/通常単体JAR版の配布方式は維持する。

- `versions/<manifest SHA256>/` にcoreと3機能JARを一式コピーして保持する。元配布物と旧版を消さない。
- `runtime/` は版に依存しない作業領域。専用user.homeとconfig/plugins/historyを用い、現用Mintの設定は自動的に読み込まない。
- `stage` はハッシュ・ZIP整合性・在庫・容量・パスを検査して新規版を準備するだけ。起動対象は変わらない。途中失敗のpending領域も削除しない。
- `activate` は現在版の期待値を照合し、履歴を先に永続化してからcurrent.jsonだけを原子的に置換する。一部JARだけを上書きしない。
- `rollback` は保持した直前の一式へselectorを戻す。壊れた現在JARを信用する必要はないが、戻す先の一式は検証する。
- 通常の `logbook.internal.Launcher` を、**選択した版の4JARだけ**を明示したclasspathで起動する。元fat JARやtarget/classesを混ぜない。
- 起動中は管理領域の排他ロックをJava子プロセスにも継承する。Pythonラッパーだけ終了しても、子が保持するロックで同時切替を拒否する。外部からの同一ユーザーによるファイル改変やロックを無視した起動は防護対象外。
- managedBundleプロパティを指定した場合だけ、既存CheckUpdateの起動時照会と単体更新画面への進入を停止する。従来の単体JAR起動では従来経路を維持する。

**アプリ一式の復元とユーザーデータの復元は別。** このツールは設定/履歴を過去へ戻さない。将来の版が非互換スキーマへ書き換えた場合まで旧版動作を保証しない。本番移行では、既存データの別コピー、形式互換性、復旧確認が追加で必要。ハッシュは利用者が確認した配布物との同一性確認であり、発行者の署名認証ではない。

## 実行の境界（開発用の新規領域のみ）

管理ツールはリポジトリのscriptsに置く。旧auto.shへ混ぜない。`init` は新しい管理領域を作成、`stage` は新しい版をコピー、`activate/rollback` はselectorだけを変更、`launch` は専用runtime内で通常アプリを起動する。

```
python3 scripts/feature_bundle_manager.py --store /new/disjoint/test-store init
python3 scripts/feature_bundle_manager.py --store /new/disjoint/test-store stage --bundle /verified/split-bundle --expected-sha256 <distribution.jsonの確認済みSHA256>
python3 scripts/feature_bundle_manager.py --store /new/disjoint/test-store activate --version <同SHA256> --expected-current none
python3 scripts/feature_bundle_manager.py --store /new/disjoint/test-store status
python3 scripts/feature_bundle_manager.py --store /new/disjoint/test-store launch
```

更新時はアプリ停止後、新版を別途stageし、確認した現在SHAを `--expected-current` で指定してactivateする。復元時もstatusを読み、`rollback --expected-current <確認した現在SHA>` を明示する。selectorの書込み後にディスク同期で失敗した場合は適用結果が不確実になり得るので、同じ操作を盲目的に再試行せずstatusと履歴を確認する。既存領域の削除やロックファイル削除でエラーを解消しない。

## 試験

Pythonの管理単体試験15件は、元/旧版保持、A→B→A、期待値競合、コピー中断、selector置換失敗、破損/混在JAR、JSON重複キー、不正パス、起動中ロック、親終了後の子ロックを確認する。

`test_managed_launcher_integration.py` は、新規の使い捨て領域で**実Launcher**をA→B→Aの3回起動する。各回メイン画面、localhostプロキシ、7機能のFXML読込元を確認し、4つのJARすべてのテスト用世代印が一致すること、設定のport/localhost制限、履歴の目印、プラグインバイト、元fat JAR、旧新版を保持したことを検査する。A/Bは同じアプリコードに異なる合成世代印を付けた試験物であり、過去の公開版や異なるデータスキーマ間の互換性試験ではない。test-only StartUpフックは製品JARに含めない。艦これへの通信・実アカウント・配備済みユーザープラグインは使用しない。

この実起動試験はMaven package後/XvfbありのPython全試験で実行する。ビルド前の静的監査ワークフローでは理由を示してスキップする。最終CIでは実行ログの `MANAGED_LAUNCH_UPDATE_ROLLBACK_OK` を確認する。検証用アプリ自身の通常の設定保存は専用runtimeに限る。
