# P3 auxiliary ownership and regression boundary

The original plan permits extraction OR a recorded reason for retaining each
function in the host, with tests. The inventory now classifies all95 top-level
internal GUI Java components:38 in the existing three feature JARs and57 host
components. No extra physical module or arbitrary-core ABI is promised.

`gui-ownership.json` explicitly records each source, owner, category, rationale and
verification entry. The checker compares every current component against the real
packager's complete additive profile; a new unclassified source, missing test link,
empty reason or owner drift fails. This structural gate is not per-class behavior
certification. Existing packaged probes exercise the extracted feature windows and
the shared runtime; grouped contract tests cover shared data, bridges and bindings.

Host retention covers the single application/timer/window lifecycle, global settings
and legacy plugin/update controls, shared mutable row adapters, public UI bridges,
shared controls, saved formation editing, WebView editor and native capture boundary.
These retained mutable adapters are not represented as fully immutable APIs.

New tests exercise synthetic PNG/JPEG encode/decode, scaled cropping, tile ordering
and padding, and white-frame game rectangle detection. Three actual JavaFX regressions
load the capture FXML without binding its native Robot, load the save window, open
and close the saved formation editor without changing its collection, plus three separate dependency GUI regressions roundtrip
Unicode/quotes/newlines/read-only state through the local WebView editor. The initial
CDN-dependent editor failure is fixed in a separate dependency change. Capture's
native setWindow/Robot/desktop-detection path remains real-device work; it is never
invoked by the FXML-only test. No real desktop, chooser, ffmpeg or private data is used.

R3 requires all17 added Java cases with zero skips plus zero unclassified components.
Real Mint/IME/capture/long-session behavior remains outside this development result.

Five additional host timer/notification GUI cases cover mission idle/completed
state, repair warning-style transitions/completion, anchorage timer stop, one-minute
notification boundary/reminder interval, and actual mission/repair bookkeeping for
once-only notification and inactive reset. Toast/audio/speech channels stay disabled;
no native delivery is claimed. All touched singleton configuration and collections
are restored. Application-session verification links now point to these actual
functional cases and real-Launcher migration tests, not logging-only wiring tests.
