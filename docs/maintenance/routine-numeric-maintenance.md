# Routine numeric data maintenance

The normal unattended lane covers 55 expedition definitions and 62 reviewed,
independently conjunctive numeric selectors listed in `routine-numeric-policy.json`.
The selectors are pure flagship minimum level or fleet total level/stat predicates.
Nine reviewed comparisons are deferred, including A5 because its sources disagree.
This scope is not certification of every rule, composition or condition.

Each daily cycle (03:17 UTC), relevant trusted master push or explicit dispatch:

1. A read-only runner retrieves both exact permitted live wiki/Zekamashi pages,
   checks freshness, unique rows, layout and agreement. Source disagreement,
   unreviewed extra numeric requirements, unsupported structure or stale facts hold
   that definition for review. No paid model/provider is invoked.
2. A fresh Git clone receives only approved numeric literals, their hash-bound facts
   and an audit JSON. The existing complete canonical R3 profile builds the real
   pack, runs Maven GUI/replay/compatibility tests, Python guards and packaged probes.
   No write credential is granted to candidate execution.
3. A separately provisioned writer checks the inert Git bundle, direct parent/tree,
   JSON-only path inventory, exact masked AST, complete pack inventory, actual R3
   summary, JAR and source receipts. It executes no candidate code. A normal
   non-force Git push rejects concurrent master movement; the current public pack
   must still equal the validated baseline. A shared concurrency group serializes
   this lane with manual data releases.
4. The writer creates a retained draft, uploads only the JSON pack, receipt and
   checksum, verifies GitHub asset digests and publishes a stable `data-v…` release
   without changing the latest application release. No application JAR is published.
5. New read-only Java21 and Java25 runners use the actual production downloader
   against the public release index, install in new synthetic stores, decode typed
   mission predicates, check idempotence, restore the retained baseline byte for
   byte and verify that the application JAR and original archive remain unchanged.
   Only their successful `cycle-complete.json` receipts prove a live cycle.

The pack starts from the actual last published baseline, preserving every unrelated
payload and its metadata. It never sweeps current unreviewed source into a release.
Ordinary changes preserve the complete AST, clause order and all nonnumeric fields.
One initial A1 transition has an exact old-public-byte hash and reviewed-source-shape
pin: old flagship20 becomes reviewed flagship5 plus fleet10. The existing dedicated
D5 trial already exercised this exact transition; no generic structural rewriting is
allowed. Maximum20 selected definitions/cycle; remaining changes await another cycle.

`no_numeric_change`, blocked source capture and deferred definitions are reported
explicitly and are not a newly completed publication. The committed source audit
separates source changes from public-baseline reconciliation, including an initial
publication when source literals already match live evidence.

If publication or either consumer fails, a separate writer withdraws only this run's
identified release to a retained draft. Assets, source commits, previous releases and
all original environments remain retained. No force-push, deletion or private runtime
rollback occurs. A subsequent failed/cancelled-cycle hold requires an operator to review the
retained evidence and explicitly dispatch `resume_after_failure=true`; rerunning a
failed job does not bypass stale master/baseline checks. Cancelled workflows require
operator inspection of any draft/public release before resuming.
