# 担当C：根拠に結び付けた季節版の実選択

作業基点：`06be3c9dd4137efbffa5d4f91800881dbc07a5ff`（PR50統合後）。
開始時とPR準備時にGitHubのmaster、open PR48/49、実head、対象コードとレビューを再確認した。
PR48の実headは`2cc9281a25b417ea9178a99f52810c6ce3bfdd4a`、PR49は`716c341599a79cd02f2be27e8d2fb32672350a16`であり、本文中の古いheadを基点にしなかった。

## 実行時の接続

`SeasonalQuestRuleService`を実際の`AppQuestCondition.loadFromResource`へ接続した。
`AppQuest.toAppQuest`の周期上書きと`QuestProgress`の集計も観測付き入口を使う。
タイトル、内部ID、同年であることだけでは選択しない。

選択には、以下をすべて必要とする。

- レジストリで明示した年度・内部ID・対象resource種別。
- 確認した期間の内側に現在時刻と任務観測時刻の両方が入ること。開始は包含、終了は排他。
- 実questlist復号時に付いた任務自身の観測日時。保存設定の日時や全APIのsnapshot日時では代用しない。
- タイトル・詳細・category・typeの一致。改行タグと空白だけを正規化し、語句・艦名の類似検索はしない。
- 24時間未満の観測。24時間はこの実装の保守的な鮮度上限であり、ゲームの公式仕様ではない。未来時刻も拒否する。
- 手動確認したidentity・期間・実装対象条件と、指定2サイトの出典記録。文字列`"true"`や資料取得だけでは確認済みにしない。
- 実際に読み込んだ旧定義と選択版の両方のSHA256。候補JSONは既存の型付きvalidatorも通す。
- 重複する同一性・期間の版がないこと。未確認の競合候補があっても都合のよい一件を選ばない。

IDだけの呼出し、保存からの復元、期間外、観測不一致、根拠不足、更新後のハッシュ不一致は未確定になる。
元のJSONと旧観測記録は保持し、旧定義を判定に使わない。通常任務と独立したカスタム任務の既存経路は維持する。
既知の季節IDに対する手動customquestは、版の根拠なしに自動承認する例外にはしない。

選択後も、`QuestCollect`入口で渡されたAppQuestのID・観測内容・観測日時を再照合する。
実戦闘・遠征・港到達の集計には版の期間を適用し、未来・不正日時も除外する。港到達は出港と到達の両方が期間内であることを要求する。
集計前、predicateの前後、画面への反映前に失効を再確認する。未確定の結果は`null`で、確認済みの0回や未達とは区別する。

## 開いたままの進捗画面

未確定理由は可視のツリーrootへ表示する。元FXMLの`showRoot=false`でメッセージが隠れないよう、状態表示時に切り替える。
版期限または観測鮮度の終了時に再読込し、古い成功表示を残さない。
表示中はquestlist更新を購読し、元の観測日時を保持した最新任務のコピーで再照合する。
更新失敗・任務消失・同じIDの異なるタイトルや条件も未確定にする。hide時に購読とtimerを止め、閉じた画面へqueued callbackを適用しない。

## 根拠が確認できた5版

旧`eventquest/*.json`を上書きせず、`logbook/seasonal/editions/`へ年度別の定義を追加した。

| 内部ID | 確認した版 | 変更した条件 |
|---|---|---|
| 840 | 2025節分 | 指定艦の旗艦・二番艦、判定JSONの`type="出撃"`を明示 |
| 841 | 2025節分 | 指定艦の旗艦・二番艦、判定JSONの`type="出撃"`を明示 |
| 843 | 2025節分 | 週次、7-5-3のTボス、明示された軽空母級の代用艦 |
| 906 | 2021桃の節句 | 週次、1-6港到達1回。B/D戦闘で代用しない |
| 954 | 2025梅雨 | 駆逐旗艦・海防2隻、対象4海域S各1回、1-6港到達2回 |

906は2022年に同じIDが単発任務へ再利用された根拠がある。954にも年度による条件差がある。
2026候補の条件比較は記録したが、指定ページで内部IDを確定できなかったためcatalogへ推定登録していない。
上記5版は2026-10-27現在すべて期間外であり、現在の任務へ適用される版が増えたとは報告しない。

期間の出典が日付だけの場合、開始日の翌日00:00 JSTから終了日00:00 JSTまでという、内側の区間だけを許可する。
これは実際の開始・終了時刻そのものの認定ではない。境界日は未確定として残す。
公式Xの指定2アカウントを実際に開いたが403だった。個別告知の取得可否と検索本文は出典記録に区別し、全文を確認したと扱わない。

出典、公開日・更新日・閲覧日、内部IDの記載箇所、確認済み条件・未確定条件、前後ハッシュは
`seasonal-source-checks-20261027.json`と`c-rule-checks-20261027.json`に記録した。

## データパック・他担当との境界

catalogと歴史版はアプリ同梱resourceで、既存6分類のdata packへ新しい能力を追加していない。
元定義のハッシュが一致する場合だけ同梱の版を選ぶ。active packで元定義が消えた場合や、内容が変わった場合は旧同梱版へfallbackしない。
catalog単独のパック更新には、能力・index・typed consumerの別途統合作業が必要であり、本PRの完成範囲に含めない。

共通編集点は`AppQuestCondition.java`と`QuestCollect.java`の読込・利用可否・期間gate。
`LogBookCoreServices.java`は既存APIで足りるため変更しない。共通差分を同ディレクトリの`seasonal-common-integration.patch`に分けた。
統合担当専有の編集controller/FXML/ArrivalConditionEditorGuiTest、Dの到達観測処理とストアは変更していない。
pom.xml、既存CI、verify_r3.sh、KQS別repoも変更しない。
