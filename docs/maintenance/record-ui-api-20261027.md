## 実装範囲

戦闘ログ・遠征ログ・開発ログの3コントローラーを `FeatureUiV1.Window` へ移行した。
表設定、選択、行番号、分割位置、ツリー列の幅・並び・ソート、確認ダイアログ、
列名取得、共通スタイルへの呼出しを公開契約へ集約した。
コントローラーの完全修飾名、既存の設定キー、FXML、保存形式、読み書きする保存先は変更しない。
`FeatureUiV1.version()` は1のまま、既存の公開シグネチャを変更せず追加だけ行う。
ツリー列の非表示機能を新規実装したものではなく、従来の幅・順序・ソート動作を保つ。

`componentLoader(owner, absoluteResource)` は所有するクラスのリソースとクラスローダーを使う。
これにより、別JAR内の非staticな集計期間ダイアログがホストのクラスローダーへ誤って戻らない。
不在リソースと相対リソースは `IOException` で拒否する。

`RecordViewsV1` は記録日時から詳細画面を開く版付き契約を提供する。
可変の `BattleLog` やホスト内部の `BattleDetail` を公開シグネチャに含めない。
FXスレッドと日時の厳密な検証を経て、既存のホスト読取・描画処理へ委譲する。
不在・読取不能の記録はfalseを返し、閲覧から移動・削除・修復・保存を呼ばない。

遠征・開発画面の行番号列が戦闘ログ用の型を誤って参照していた箇所も、実際の行型へ修正した。

## 新たに確認した未解決課題: 旧形式の経験値欠落

再現条件: `SimpleBattleLog` が受け付ける14列の旧形式CSV（経験値の63/64列がない）を
記録一覧の詳細行へ変換する。`BattleLogDetail.toBattleLogDetail` が空文字を
`Integer.parseInt` へ渡すため `NumberFormatException` になる。
基点7004a3eの同メソッドにも同じ実装があり、今回変更していない。

不足値を0で捏造したり、履歴へ追記して形式を変更したりせず、
「未記録」の表示・並び替え・集計・コピーを含む扱いを設計して回帰試験することが必要。
今回の現行形式試験の成功を、旧形式の修復完了や全履歴互換の証明にはしない。
旧形式失敗の試験ログは保持したままで、課題は未完了とする。
