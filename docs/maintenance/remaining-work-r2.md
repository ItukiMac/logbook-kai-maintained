## 契約と制限

`LogBookCoreServices.pinDefinitions()` は同一スレッドで逆順に閉じるスコープ。既存のresource URLも取得時の不変バイト列を保持する。ロード済み任務/遠征条件には取得時の世代を紐付ける。破損・不正な型/演算子・欠損必須値は公開前に拒否し、旧版と通知番号を維持する。ユーザーのcustomquestは管理パックに取り込まず、外部JSONの上書き/削除はしない。

新しいメニュー「ゲーム定義を再読み込み」は設定済みのローカル定義をメモリーへ読み直す操作だけで、ダウンロード、インストール、active.jsonの書換えはしない。ネットワーク自動更新は有効化しない。

通知ストリームはContentListenerSpi.acceptの呼出期間に限る借用。非同期拡張は呼出中に必要な解析結果をコピーする。遅い/割込みを無視する第三者プラグインを強制終了しないが、待ちキューと捕捉生バイトは制限される。制限は全JVMヒープ/第三者プラグイン独自コピーの上限ではない。解凍上限違反も通信は転送し、捕捉データを正常通知しない。

状態sequenceは処理されたAPIハンドラー群の順序。ネットワーク要求の時系列や全ゲームオブジェクトの鮮度を保証するものではない。updateSucceeded=falseは部分失敗を示す。既存可変beanへの全UI書込みをスレッド安全化したという主張でもない。公開モデルには生HTTP/認証情報を含めない。

FeatureModuleの3プロバイダーは現時点でホストJAR内。実メニューの登録経路は分離したが、全アプリケーションの物理的な複数JAR化はしていない。JAR単体の既存更新・復元経路を維持するため、配布形態の変更は別の移行設計を要する。

## 予算・出典・承認

候補計画は `--candidates` の完全な提案JSON、任意の `--approvals`、`--previous` を入力し、結果を標準出力へ出す。既存ソース・設定を変更しない。`--max-candidates` が新規処理件数を制限し、入力/出力tokensおよびmicro-USDの申告上限は既定0。未知/不足予算を黙認しない。

出典はwikiwiki.jp/kancolle、zekamashi.net、指定公式Xの個別投稿URLに限定し、未来/30日超/タイムゾーン欠落の確認時刻を受理しない。ただし、記録の出典ハッシュと承認者はローカルの申告証跡であり、暗号学的な発行者認証ではない。費用は保守的に申告された見積りの予約で、実際のLLM課金・トークン計測ではない。このツール自体は有料APIを呼ばない。承認済みでもJavaの消費モデル検証が別に必要。

## 検証手順（本番を対象にしない）

1. `python3 tools/build_data_pack.py --source-sha <対象コミット>` で追跡済み152件から実パックを生成。
2. Xvfb下のJava21/25で `-Dlogbook.gui.tests=true -Dlogbook.test.dataPackPath=target/logbook-data-pack.zip verify`。
3. `tools/tests`、`scripts/tests`を実行し、全ゲームJSONを新規監査する。
4. KQSは新/旧ホストJARに対して4スイートを実行。新ホストでは、30回の世代切替に並行する20エクスポート/2000条件の同世代性を確認する。
5. KLBは従来の固定ソースを新ホストに対してコンパイルする。配備済みバイナリの実通信認証とは区別する。

## 保留を完了扱いしない項目

* 最新ゲーム条件の全85任務と63遠征を外部出典と個別に突き合わせる作業は、このコード変更だけでは完了しない。構文/型/実行安全性と、ゲームの条件が現在正しいことは別。
* 自律的なWeb差分からの条件推定、実際のプロバイダー請求計測、無人変更/マージ/配布を有効化していない。候補の計画・証跡・承認までが今回の実装境界。
* 全機能の物理JAR分割、MintのGUI/日本語IME、実Chrome/艦これ通信、配備済みKLB/KQS、実配置での更新復元は別段階。
* 過去PR35の自動再レビューが実行中である件は、実際の完了結果を読むまで未確認として保持する。

本番JAR、auto.shのdry-run、設定、履歴、画像、既存プラグイン、旧版・バックアップを変更/削除しない。Release/タグを作成しない。今回の実行番号、確認したコミット、成功/スキップ件数はPRの検証記録に記載する。
