## 先行できる開発残件（Mint待ちではない）

1. **D4-consumers**: 新APIを既存の読込口・型付きキャッシュへ接続する。各処理が一度取得した同一スナップショットを保持し、全消費者を準備できるまで起動中切替を有効にしない。GUI/任務/KQSの世代IDと結果一致を隔離試験で確認する。
2. **P1-state / P3**: 可変ゲーム状態の読取モデル、イベント順序/寿命、旧KLB/KQSとの互換境界を確定してから広域プラグイン分割する。定義APIだけで全P1を閉じない。
3. **D2-semantics / M1-candidates**: 動的参照とキャッシュの実消費を照合し、ゲーム条件・最新定義の出典/差分/意味を検証する。構文合格や85件の型変換だけで任務内容の正しさを保証しない。
4. **L4-capacity / P2-feedback**: 捕捉データ総量とキュー/長時間異常系を検証し、上限時に半端な捕捉結果を正常データとして通知しない設計を行う。確率計算の入力拒否理由を既存画面へ表示する。
5. **M1-orchestration**: 候補選定・承認・再開履歴・実際の費用/トークン制御を分離する。現段階では定期実行/自動マージ/無人更新を有効化していない。

## 棚卸し・検査の実行と境界

`python3 scripts/maintenance_inventory.py --root .` は追跡済みJava/リソースJSON/pomだけを読み、参照候補/ハッシュをJSONで標準出力に出す。個人のconfig/logs/plugins/バックアップは走査しない。静的候補は全実行時参照/全キャッシュの網羅保証ではない。

`python3 scripts/audit_game_json.py --root .` は管理対象のゲームJSONだけを新規構文検査する。`--max-files` と `--previous` の再開仕様は `json-audit-resume.md` を参照。エラー/未処理/既存証跡再利用を区別し、空の対象集合を全件合格としない。CLIはソースを書き換えず、出力保存は別名ファイルに行う。
