# 艦娘の手動ラベル編集を本体の更新APIへ分離 — 2026-10-28

基点はPR61の読取契約 `546b196122a4f824c724e222927e9885f6bc451e`。
本変更の実測・最終head・結合CI・統合結果は対応PRへ記録する。作成時点で未実行の試験を合格とはしない。

## 機能

`ShipLabelsV1.capture` で、確認画面を開く前に対象艦ID・艦種の内部ID・既存の手動ラベルを変更不能な値へコピーする。
ユーザーの確定後だけ `add` / `remove` を呼ぶ。画面が `ShipLabelCollection` のMapを直接書き換えない。

本体 `ShipLabelService` は全対象の存在・ID・元ラベルを先に確認する。
最後の対象に競合や不正状態があっても、先に調べた艦だけ変更することはない。
古い確認内容での上書きは拒否し、変更を行わず再選択を案内する。
変更する文字列は従来どおりそのまま保持し、空白を勝手にtrimしない。
同じラベルの再追加や、存在しないラベルの除去は無変更として扱う。

削除対象は明示的に選ばれた手動ラベルだけ。最後の手動ラベルを外したときのみ、その艦の空Mapエントリーを除く。
他のラベル、他艦、`Ship.sallyArea`、戦闘履歴、ゲームサーバーには変更を行わない。
イベントの出撃札はゲーム管理のため、手動ラベル除去ダイアログの候補に含めない。
出撃札と同名の手動ラベルを外しても、出撃札の表示は保持する。

既存のConfigによる保存・バックアップ、ファイル名、JSON形、メニュー、設定キーを変更しない。
更新API自体は `Config.store` やファイル削除、ネットワーク通信、ゲーム操作を呼ばない。
通常のユーザー操作による保存時期は従来のまま。

## 限界と継続事項

更新API同士は同じ本体ロックで直列化する。ただし、旧プラグインがbeanを直接書く経路や、全通信writerはこのロックに参加していない。
したがって全ゲーム状態のトランザクション、全writer同期、外部プラグインまで含む原子的更新を保証したものではない。
未参加のwriterとの競合可能性は残る。全P1完了とは扱わない。

艦娘一覧の表示用 `Ship`、表・画像・フィルターの旧型、艦娘画面の物理JAR分割はまだ残る。
本体＋3機能JARの配布契約を変更せず、任意本体版との互換やホットリロードも追加しない。
全148定義の全条件認証、未確定季節版、未知データ形式の変換、Mint実機・IME・Chrome・実ゲーム・本人データ・長時間稼働、Release/タグ公開、本番適用も別の未完了として保持する。
