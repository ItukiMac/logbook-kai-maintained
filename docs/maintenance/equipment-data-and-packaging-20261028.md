## 今回の実装

```text
装備・装備マスター・搭載艦の既存状態
  → 本体 EquipmentDataService
  → EquipmentDataV1 の変更不能な値と一覧
  → status機能JARの所有装備一覧（一般装備／基地航空隊向け装備）
```

- `EquipmentDataV1` は装備定義と個数、所持インスタンス、所有艦の表示情報、航空機の計算済み値、分類を提供する読取専用API。
- データAPIの公開シグネチャにJavaFXや既存の可変beanを出さない。値はrecord、返すList/Mapと分類の内部Listも変更不能。
- 所有艦の通常スロットと増設スロットを同じ索引で扱う。装備詳細は元の `Ship` を保持せず、IDと表示名などのコピーを使う。
- 装備数は取得した所持一覧を一度集計する。装備マスターごとに所持全件を再走査する旧画面経路を置き換える。速度改善率の実測を行ったという意味ではない。
- 制空・半径・配置コストは従来の `AirBases` / `Items` の計算を再利用し、計算式を別実装しない。ゲーム仕様そのものの再認証ではない。
- 所持一覧にマスター不明のIDがあってもインスタンスは残し、定義値を捏造しない。警告を返し、定義・分類が確認できる行を表示する。
- 一般装備の詳細ソート、通常/増設の所有者、数値/テキストフィルター、改修可能日による選択、既存のメニュー名・FXML・設定キーを保持する。
- ロックされた装備の既存外部向けJSON出力は、同じキー・並びを維持する。

## 実配布の変更

親 `ItemController` と子タブ `ItemItemController` / `ItemAirBaseController`、その内部セル、
新しい投影ヘルパーと詳細行、`item.fxml` / `item_item.fxml` / `item_airbase.fxml` をstatus JARへ配置する。
これは**1つのウィンドウの2タブ**であり、独立した3ウィンドウを追加した数え方はしない。
本体＋3機能JARと7登録機能IDはそのまま。新しい第4の装備モジュールは作らず、更新単位はstatusである。
記録画面のchartsプロファイルとは独立に共存する。

追加プロファイルは `equipment_ui_profile: equipment-ui-in-status-v1`。
本体に `EquipmentDataV1.class` がある場合と対応させ、次を検査する。

- 新しい本体でのプロファイル欠落、未知値、旧本体への偽のプロファイル追加。
- 装備画面が本体に残る状態、status以外のJARへの配置、必須クラス/FXMLの欠落。
- 正規の新規領域への配布生成と入力JARの不変性。

元から装備データAPIを持たない旧v2配布は、従来どおりプロファイルなしで検証できる。
新しい配布には同梱の更新済み検証器を用いる。古い検証器が新プロファイルの保証まで行えるとは主張しない。
同一coreハッシュ、依存、JAR所有、メタデータ、版番号再利用防止などの既存検査を緩めない。

## 維持した境界と限界

| 項目 | 現状 |
|---|---|
| 取得後の値の不変性 | APIで保証。元beanや入力Listを後から変更しても取得済みの値は変わらない |
| 通信更新と読取の原子性 | 未保証。旧writer全体の同期を変更していない。複数の読取呼出しは異なる状態を見得る |
| 重複した所有者の観測 | 従来の先に観測した所有者を選ぶ扱いを保持。通信欠落・不整合状態の完全解決とはしない |
| 画像 | `EquipmentImagesV1` がFXスレッドで本体の現在の画像生成へ委譲。画像まで凍結したsnapshotとはしない |
| 画面設定 | 従来の設定beanと保存キーを維持。全設定APIを不可変化する変更ではない |
| 共通GUIヘルパー | パラメータフィルター、補完、旧 `Item` / `AirBaseItem`、DeckBuilder等は共有の本体側に残る |
| クラスローダー | 製品の共有クラスローダーを維持。完全な別ローダー隔離・任意core間互換ではない |
| 旧公開型 | `Item.toItem` / `AirBaseItem.toAirBaseItem` / `DetailItem.toDetailItem` 等を削除・変更しない |
| ゲーム状態・保存記録 | APIに変更・削除・変換を追加しない。明示的な既存CSV保存/クリップボード操作は従来どおり |

表操作とウィンドウのライフサイクルは `FeatureUiV1` を使用する。
既存の保存ダイアログと親子チェックボックス連動を公開GUI契約へ追加したが、既存メソッドの署名と版1を維持する。
