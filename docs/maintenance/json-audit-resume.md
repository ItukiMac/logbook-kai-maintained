# A/D/M: full tracked game JSON syntax audit with bounded resumption

`python3 scripts/audit_game_json.py --root .` reads Git-tracked game definition JSON only, prints JSON to stdout and never changes source/runtime files or performs network/LLM requests. It supports legacy // and /* */ comments while preserving strings, rejects malformed/trailing JSON, duplicate object keys and non-finite constants. Symlinked/missing/oversized files are errors rather than silently omitted. Empty selection is an error, not a successful full audit. Valid large JSON numbers are parsed as Decimal rather than rounded to floating-point infinity; this is syntax validation, not a consumer numeric-range guarantee.

`--max-files 20` bounds fresh parse attempts. Capture stdout to a NEW report filename. A later invocation with `--previous previous-report.json --max-files 20` can reuse matching path/SHA256/validator evidence, including previous parse errors. An unchanged malformed file remains an error but does not consume the next run's parse budget, allowing later pending files to advance. Changed or repaired bytes are freshly parsed. Current path safety and file bytes are always rechecked. Missing/unsafe paths remain fresh filesystem errors but do not consume parse-attempt capacity.

`validated`, `reused`, `reused_errors`, `attempted`, `pending` and `errors` are distinct counts. Cached failures remain entries with `status: error` and `evidence: reused`; they can never make `complete` true. Errors take exit-code precedence (1), otherwise pending work exits 2; complete success exits 0. Validator v2 deliberately rejects older validator reports. Treat previous reports as trusted local evidence, not authenticated attestations. CI performs a fresh full audit without cache reuse.

Fifteen new audit tests plus the ten existing inventory tests cover the safety/resumption boundaries. This controls validation work units, not financial/token spending: no paid API is called. It does not validate semantic quest correctness, resolve all dynamic Java lookups, update definitions from external sources, enable periodic jobs, automatically commit/merge or deploy. Those remain separate M/D tasks.
