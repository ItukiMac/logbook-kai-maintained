# Linuxで旧logbookと並行試験

この配布物は実機試験候補です。旧環境を維持し、新しい保存先で起動します。
必要環境: LinuxのGUIセッション、JDK 21、Python 3、Chromium系ブラウザ。JavaFXを動かすGTKなどのライブラリが必要です。ブラウザ拡張は同梱の未パッケージ版を使用します。

## 1. 現状を記録

旧logbook/KLBのフォルダー、起動方法、拡張のバージョンと読み込み元を控えます。
次のコマンドでポートを確認します（参照のみ）。

```sh
ss -ltnp | grep -E ':(8888|8889|8891|8892)\b'
java -version
python3 --version
```

旧bridgeは8891、新bridgeは8892、新プロキシは8889を既定とします。新ポートが使用中なら別の空きポートを指定します。

## 2. 新規フォルダーへ展開して準備

ZIPを新しいフォルダーへ展開します。以下は展開したキット直下で実行してください。起動スクリプトがこのキットの絶対パスを参照するため、作成後にキットを移動しません。

```sh
python3 scripts/prepare_parallel_runtime.py \
  --bundle ./bundle \
  --store "$HOME/logbook-kai2-test" \
  --bridge-port 8892 --proxy-port 8889
```

保存先が既存なら処理は拒否されます。異なる新規名を選んでください。データはその保存先のruntime配下、更新世代はversions配下です。旧環境への書き込みは行いません。自己更新・自動データ更新は管理起動で無効化されます。

```sh
"$HOME/logbook-kai2-test/launch-kai2.sh"
```

## 3. ブラウザ拡張を一つだけ接続

旧拡張は削除せず、まずCDP停止して無効化します。拡張管理画面の開発者モードから、キット内のextensions/browser-bridgeを「パッケージ化されていない拡張機能」として読み込みます。

同じゲームタブに旧拡張と新拡張を同時接続しません。新拡張一つが、同じ取得データを旧8891と新8892へ送ります。カスタムポートを使う場合は拡張オプションにも同じ値を設定します。

拡張でCDP開始後、ゲームを再読込して現在情報を揃えます。再接続の間に完了した任務など、履歴は再取得できない場合があります。

## 4. 試験と合格基準

| 確認 | 合格基準 |
| --- | --- |
| 接続 | 両方のhealthが応答し、拡張の旧版/kai2の状態が接続中 |
| 現在情報 | 同じ観測時点の艦娘数、装備数、資材が一致 |
| 記録 | 新規記録がそれぞれのフォルダーへ保存される |
| 任務 | 受諾・解除・報酬受領が反映され、再起動後も完了が残る |
| 手動補正 | 理由付き更新が保存され、後続観測との不一致を確認できる |
| 情報出力 | JSON/CSVのプレビュー・コピー・保存が動作 |
| kai2停止 | 旧版への送信が継続し、kai2失敗が拡張に表示される |
| 復帰 | kai2を再起動しゲームを再読込して現在情報を再取得できる |

```sh
curl --fail http://127.0.0.1:8891/health
curl --fail http://127.0.0.1:8892/health
```

kai2送信は順序を保つ独立キューです。最大32件/64MiB、1件5秒で打ち切ります。失敗・容量超過は件数表示し、自動再送はしません。拡張の再起動でメモリー上の待機通信は失われます。失敗や欠落があった区間は完全一致の比較対象にせず、再読込後から比較します。

## 5. 試験終了・旧構成へ復帰

新拡張でCDP停止して無効化し、旧拡張を有効化して再接続します。kai2はウィンドウから終了します。両環境のデータとキットは保持します。旧フォルダーへコピーし戻す操作は不要です。

## 6. kai2の世代切り替え

アプリ停止後、同梱scripts/feature_bundle_manager.pyのstage/activate/rollbackを使います。`--help`で構文を確認してください。切替はアプリJARだけを対象とし、ユーザーデータを巻き戻しません。戻す前にruntimeを別途コピーして保持してください。
